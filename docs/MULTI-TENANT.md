# 多租户目标架构（一云多用户 · 后置）

> **当前产品主路径仍是：家用 PC + NapCat + 本机网关。**  
> 本文只描述远期云多租户方向，**仓库内已无独立协议栈 / 公共 sign 实现**。

## 产品目标

| 要求 | 含义 |
|------|------|
| **一台云服务器服务多人** | 不是一人一机装服务 |
| **用户只碰 Shell** | 装/用客户端，填服务器地址，扫码登录 |
| **用户不接触服务器** | 不装 NTQQ、不配 NapCat、不 SSH |
| **消息经云端代理** | Shell 只拉数据 + 展示 |

## 和本机网关的关系

| | **本机网关（现状）** | **云多租户（后置）** |
|--|---------------------|---------------------|
| 谁持号 | 用户家 PC + NapCat | 云上每用户会话 |
| 登录 | 用户自己在 PC 登 NTQQ | 远端扫码 / 云侧持号 |
| 适合 | 自用、少数可信设备 | SaaS 式任意用户 |

实现多租户时需要另选可多会话的协议后端与**服务器侧**签名方案；**不要**把 sign token 下发给终端用户。

## 目标会话模型

```
WebSocket 连接  ──bind──►  AccountSession (sessionId)
                              │
                              ├── ISessionBackend（独立消息缓存）
                              ├── 订阅者: 1..N 个 Shell 连接
                              └── prefs_{uin}.json
```

- 新连接默认**无会话**。  
- `configureAccount` / 登录流程 → 创建或绑定会话。  
- **禁止**「一个 Broadcast 打给所有连接」导致串号。

Shell 只填：服务器主机、访问凭据；（可选）期望 QQ 号。
