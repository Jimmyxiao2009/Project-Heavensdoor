# 本机 NapCat 网关 + OpenFrp 出门方案

和 MC 开服同一套路：号挂在家里电脑，OpenFrp 只把网关端口映射出去。

```
家里 PC（常开、勿休眠）
┌──────────────────────────────────────────────┐
│  NTQQ 已登录 + NapCat（HTTP/WS 仅本机）         │
│  QQReborn.RealServer  监听 0.0.0.0:8765         │
└──────────────────┬───────────────────────────┘
                   │ 只映射 8765
                   ▼
              OpenFrp 隧道
                   │
     在家：Shell → 127.0.0.1 或 局域网 IP
     出门：Shell → OpenFrp 给你的 域名/IP:远程端口
```

**不要**把 NapCat 的 `3000/3001` 映射出去，只映射 **RealServer 的 8765**。

---

## 一、家里准备

1. 启动 NTQQ + NapCat（已登录）
2. 启动 QQ Reborn 管家 / 网关，确认本机：
   - `http://127.0.0.1:8765/`
   - `ws://127.0.0.1:8765/ws`
3. 设置并复制 **网关访问密码**（不是 QQ 密码）
4. 系统电源：**禁止休眠**

---

## 二、OpenFrp 隧道怎么建

在 OpenFrp 面板新建一条 **TCP** 隧道（推荐）：

| 项 | 填法 |
|----|------|
| 隧道类型 | TCP |
| 本地地址 | `127.0.0.1` |
| 本地端口 | `8765` |
| 远程端口 | 面板分配 / 自选（例如 `57442`） |
| 访问地址 | 面板显示的节点域名或 IP |

Windows 上打开 **OpenFrp 客户端/启动器**，登录后启用这条隧道，状态为在线。

外面实际连的是：

```text
ws://{OpenFrp访问主机}:{远程端口}/ws
```

---

## 三、Shell 怎么填

| 场景 | 服务器主机 | 服务器端口 | 访问密码 |
|------|------------|------------|----------|
| 在家、同机 | `127.0.0.1` | `8765` | 管家密码 |
| 在家、同 WiFi | 电脑局域网 IP | `8765` | 管家密码 |
| 出门 | OpenFrp 面板的访问主机/域名 | **远程端口** | 同一管家密码 |

注意：

- 主机框只填主机，不要带 `ws://`（也可以整段粘贴，新版本会自动拆）
- 端口填 **OpenFrp 远程端口**，不是家里固定 8765（除非你刚好申请到 8765）
- 密码必须与管家一致；改密后要重启网关

---

## 四、为什么有时连上有时连不上

OpenFrp 和樱花一样，都是 FRP 链路，常见原因：

1. OpenFrp 客户端未开 / 隧道离线
2. 家 PC 休眠或网关进程挂了
3. Shell 仍填着 `127.0.0.1`（出门必须改成 OpenFrp 主机）
4. 端口填成了本地 8765，而远程口其实是别的
5. 节点波动 / 冷启动慢

0.1.0.6 起 Shell 对公网/Frp 主机：

- 连接超时约 **28s**
- 握手最多 **3 次**重试
- 断线后更快自动重连

若仍 `第3/3次` 超时，优先查 OpenFrp 隧道是否在线，而不是密码。

---

## 五、自检顺序

1. 家 PC：`http://127.0.0.1:8765/backend` 能打开
2. OpenFrp 客户端：隧道绿色/在线
3. 手机流量环境：Shell 主机/端口改成 OpenFrp 访问信息
4. 密码与管家一致
5. 再点「开始连接」

---

## 六、安全

| 建议 | 原因 |
|------|------|
| 只映射 8765 | 3000/3001 是 NapCat 管理面 |
| 强访问密码 | Frp 暴露公网时的门槛 |
| 不要提交 OpenFrp token | 与本地密钥同等对待 |

当前产品主推：**本机网关 + 任意 Frp（OpenFrp / SakuraFrp 等）只映射 8765**。
